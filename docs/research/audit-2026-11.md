## 2. Defects found on `main` and fixed

Each was reproduced before the fix and is covered by a regression test.

| # | Defect | Effect | Fix |
| --- | --- | --- | --- |
| 1 | `crystaltwin_bridge.verify_report` and `make_report` used plain `json.loads` | Duplicate keys (`"hardwareExecuted": true, "hardwareExecuted": false`) and `NaN` passed `--verify`, while the proposal gate refused the same bytes | Bridge uses the gate's strict reader |
| 2 | `verify_report` checked named fields only | A report with added `measuredOnHardware: true`, `physicalDevice`, `speedupVsCpu` verified as valid | Exact field sets at every level of the report |
| 3 | Dict `==` in `verify_report` and `make_review` | Python's `True == 1 == 1.0` let `0`, `1`, `0.0` stand for the boolean safety flags and `False`/`True` for channel numbers | JSON-typed equality (`_same_json`); numbers still compare by value so `100` equals `100.0` |
| 4 | `generatedAt` and `disclaimer` were never checked | The non-claim disclaimer could be replaced by a claim | Timestamp must parse with a UTC offset; disclaimer must match |
| 5 | `gari_evidence.parse_author_si1000_csv` | Short row raised `AttributeError`, not `ValueError`; `int()` accepted `1_000`, `+5`; `float()` accepted `infinity`, `4_0.0` | Explicit column check and ASCII-decimal parsing |
| 6 | `orchestration._decode` had no `parse_float` guard | `1e999` became `inf` and was only caught later by per-field checks | Refused at parse time |

Defects 5 and 6 only applied with `enforce_upstream_blob=False` or were caught
downstream; they are listed because fail-closed behaviour should not depend on
a later check.

**Compatibility.** `qfabric-crystaltwin-report/1`,
`crystaltwin-qfabric-snapshot/1` and `qfabric-research-proposal/1` are
unchanged: every document the generators write still verifies. Only documents
the generators never wrote are newly refused.
